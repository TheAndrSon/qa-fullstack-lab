# Ручное тестирование: шаблоны и упражнения

## Тест-план (шаблон)

```markdown
# Тест-план: <фича>

## Цель
Что проверяем и зачем.

## Область
- В скоупе:
- Вне скоупа:

## Окружение
- URL, браузер, ОС, тестовые пользователи.

## Тестовые данные
- Пользователи, товары, промокоды.

## Риски
- Что может сломаться и почему.

## Подход
- Функциональное, негативное, граничные значения, API, UI.

## Критерии входа/выхода
- Когда начинаем и когда считаем готовым.

## Результаты
- Ссылка на чек-лист, баги, отчёт.
```

## Чек-лист ShopSphere

- [ ] Удаление товара.

## Баг-репорт (шаблон)

```markdown
**ID:** BUG-001
**Заголовок:** Отрицательное количество в корзине уменьшает итог
**Окружение:** Chrome 157, Windows 11, http://127.0.0.1:8000
**Шаги:**
1. Войти как alice.
2. Добавить товар.
3. В корзине указать -5.
4. Нажать «Обновить».

**Ожидаемо:** количество не может быть меньше 1.
**Фактически:** количество -5, итог отрицательный.
**Severity:** High
**Priority:** High
**Evidence:** screenshot/2026-11-13/cart-negative.png
**Комментарий:** воспроизводится в API `POST /api/cart`.
```

## Severity / Priority

- **Blocker** — нельзя пользоваться, нет обхода.
- **Critical** — потеря данных/денег, безопасность.
- **Major** — ключевая функция сломана, есть обход.
- **Minor** — косметика/неудобство.
- **Trivial** — опечатка.

Priority — насколько срочно чинить для бизнеса; не всегда совпадает с severity.

## Тест-дизайн

- Эквивалентные классы.
- Граничные значения (0, 1, max, max+1).
- Попарное тестирование.
- Таблица принятия решений.
- State transition (корзина → checkout → заказ).
- Негативные сценарии и обходы.

## Полный цикл (упражнение)

1. Выбрать фичу (например, checkout).
2. Написать тест-план.
3. Пройти чек-лист вручную.
4. Оформить 3–5 баг-репортов.
5. Автоматизировать API-сценарии.
6. Автоматизировать 1–2 UI-сценария.
7. Добавить тесты в CI.
8. Открыть PR, пройти review, merge.
